## 4. Exact Split-Root Reconstruction Geometry

Each future prospective or authorized attempt binds five pairwise-distinct
direct children of one fresh control-root attempt:

```text
legacy_source_root
complete_input_root
isolated_output_root
producer_run_dir
matching_audit_run_dir
```

The isolated HOME is a sixth distinct child. All are absolute, non-aliased,
non-symlink, and disjoint from canonical, legacy, golden, runtime overlay,
driver, launcher, old attempts, and external guards.

### 4.1 Clean legacy source root

`legacy_source_root` is one fresh detached Git worktree at exact commit
`8fb8608c...6ada`.

Before and after every zero-science Phase-A probe, and before/after future
producer and audit children, it must have:

- exact `git rev-parse HEAD`;
- exact empty `git status --porcelain=v1 -z --untracked-files=all`;
- the exact tracked `src` path list and 48 source records;
- every tracked source regular, non-symlink, nlink-1, exact hash/size/path;
- no complete-input materialization, manifest, output, cache, bytecode,
  lock, temporary, partial, or quarantine path;
- byte/stat/inode identity unchanged across producer and audit.

The source manifest retains schema
`t4as_legacy_reconstruction_source_manifest_v1` but now requires
`git_status_records == []`. The old allowance that interpreted complete
input deltas inside the source worktree is removed for reconstruction only.

### 4.2 Complete input root

`complete_input_root` begins as a fresh empty 0700 ordinary directory, not
the legacy source worktree. T4 materializes exactly the complete-290 target
view below it.

The input manifest retains schema
`t4as_legacy_reconstruction_input_manifest_v1` and must bind:

- exactly 290 entries in the frozen Python code-point contract order;
- exactly 290 unique roles, repository-relative paths, and target inodes;
- every target regular, non-symlink, nlink-1, read-only, exact size/hash;
- target absolute path exactly
  `<complete_input_root>/<target_repository_path>`;
- every source/target pair inode-distinct and every source outside the input
  root;
- no target or directory aliasing the legacy source root;
- the three-field canonical contract exactly
  `77927103...fd24`;
- the exact clean-source-manifest SHA;
- a complete post-materialization tree inventory containing only the 290
  target files and their necessary directories, with no output, manifest,
  cache, bytecode, lock, tmp, partial, or quarantine file.

The manifest files themselves remain in the attempt control root, outside
both source and input roots, and are separately immutable-bound source files.

### 4.3 Process cwd and runtime source

For reconstruction producer and matching audit:

```text
process cwd / allowed cwd root
  complete_input_root
--detached-root
  legacy_source_root
PYTHONPATH
  frozen overlay : legacy_source_root/src
runtime project root
  legacy_source_root
output root
  isolated_output_root
```

The unchanged launcher therefore validates a clean scientific source and
imports exact legacy code from it, while the unchanged Table-I
repository-relative input reads resolve from the complete input root.

No field may collapse these two roots. The driver must explicitly route:

- launcher argv `--detached-root`, source manifest, Git/source validation,
  imported-module origin, runtime project root, and runtime source/cache
  guards to `legacy_source_root`;
- request cwd/allowed cwd, input manifest, and repository-relative input
  reads to `complete_input_root`;
- output and pair validation to `isolated_output_root`.

The unchanged launcher need not receive a new CLI argument: the durable
driver already binds and launches the exact cwd. Adding a wrapper, alternate
launcher, `-c`, stdin code, sitecustomize, import hook, or extra command
argument is forbidden.

## 5. Driver Changes Required In Phase A

Only the artifact-local durable control driver and artifact-local
solver-free tests/evidence may change.

The repair must:

1. preserve both T4as reconstruction phase literals and all older phases;
2. preserve `_expected_reconstruction_command()` and the exact launcher
   argv except that its `--detached-root` value is explicitly the clean
   source root;
3. make reconstruction request `cwd` and `allowed_cwd_root` equal the
   complete input root;
4. make reconstruction runtime binding/environment use the clean source
   root and exact `<source>/src`;
5. make `_request_runtime_project_root()` return the bound clean source root
   for both reconstruction phases instead of returning cwd;
6. validate `cwd == cwd_root == input_root`, while requiring
   `input_root != detached/source_root`;
7. include source, input, output, HOME, producer-run, and audit-run roots in
   exact distinctness, direct-child, containment, overlap, alias, link, and
   post-drift gates;
8. validate the source manifest against the clean source root and require an
   empty status;
9. validate all input targets against the separate input root;
10. make post-producer and post-audit validation recover the clean source
    root from the reconstruction binding rather than substituting audit cwd;
11. require producer and matching audit to carry byte-identical source/input
    roots, manifests, environment, runtime, and pair provenance;
12. keep the exact T4as durable request/prelaunch/running/receipt/stream/
    final/control/failure/replay and process semantics unchanged.

No general relaxation of cwd/source identity is permitted. The split applies
only to the two exact reconstruction phases.

## 6. Required Zero-Science Phase-A Evidence

T4at Phase A does not execute the reconstruction launcher, optimized runner,
official audit, `_compute_frequency()`, or any solver.

Required positive tests:

- exact split-root prospective producer request validates;
- exact split-root prospective matching-audit template validates;
- clean source HEAD/status and all 48 tracked source records validate;
- complete input root independently validates all 290 entries and contract;
- exact CPython 3.14 import-only probe under
  `cwd=complete_input_root` and
  `PYTHONPATH=overlay:legacy_source_root/src` imports the required legacy
  modules only from the clean source root;
- the import-only probe reads/validates the frozen Table-I input identities
  without calling `_compute_frequency()` or any solver;
- source and input trees are byte/stat/inode unchanged after the probe;
- old accepted non-reconstruction request behavior remains unchanged.

Required negative tests:

- source root and input root identical;
- input root inside source root, source root inside input root, inode alias,
  symlink, hardlink, or non-direct child;
- dirty source status, wrong source commit, missing/extra/drifted tracked
  source, or input target materialized below source;
- cwd/allowed cwd not equal to input root;
- runtime project root or `PYTHONPATH` bound to input root;
- imported `schwgw` origin below input root, primary checkout, or any
  alternate source;
- missing/extra/writable/linked/aliased/wrong-role/wrong-path/wrong-hash/
  wrong-size/duplicate-inode input;
- input source inside the input root or source/target shared inode;
- source/input/output/HOME/run-root overlap or wrong parent;
- producer/audit source root, input root, manifests, cwd, environment,
  runtime, pair, or terminal provenance mismatch;
- post-bind source or input mutation;
- any launcher/runner/solver/audit invocation during Phase A.

Static AST/dataflow checks must prove that the reconstruction launcher hash
and its scientific dataflow are unchanged, and that split-root logic is
unreachable from all other driver phases.

T4 may use fresh immutable no-overwrite roots to correct diagnosed
pre-execution, zero-science, artifact-local helper/fixture/manifest/path/
serialization/bookkeeping/test defects until the exact checkpoint. Each
failed root remains immutable and each correction has a concrete diagnosis;
blind retry is forbidden.

Phase A returns only:

```text
CHECKPOINT / LEGACY RECONSTRUCTION SPLIT-ROOT INPUT VIEW FROZEN
```

The checkpoint must report the old/new driver diff and SHA, exact unchanged
launcher, source/input/root manifests, import-only captures, every positive
and negative test, runtime/input/legacy/golden/canonical guards, and exact
counts:

```text

```

## 7. Later One-Shot And Phase-C Boundary

Only after root T0 independently audits the Phase-A checkpoint may it issue
one new digest-bound:

```text

```

That later attempt must create fresh source/input/output/HOME/run roots; it
must not reuse the T4as failed roots or T4at Phase-A prospective roots.

One producer may call the unchanged exact-legacy `_compute_frequency()`
exactly once. Only full durable/scientific/pair PASS may start one matching
zero-solver reconstruction audit. A launched producer or audit failure
consumes the new authorization and forbids retry.

Complete producer plus matching-audit PASS returns:

```text
CHECKPOINT / LEGACY RAW-WARNING WITNESS PASSED
```

Root T0 must independently audit it. The next step is still the separately
gated, zero-science T4ar Phase C:

```text

```

Only Phase-C PASS and a further root-T0 audit may authorize a new matrix
`2.91875` one-shot. Matrix order remains
`2.91875 -> 3.759375 -> 3.89375 -> full 241x241`.

## 8. Prohibitions

Forbidden:

- mutation, deletion, chmod, rename, repair, reuse, or reinterpretation of
  the consumed T4as failure root, locks, or any older attempt;
- weakening or removing the launcher's clean-source check;
- materializing any accepted input under the clean source root;
- changing the reconstruction launcher, `_compute_frequency()` call,
  scientific imports, arguments, warning capture/filter/allowlist/count,
  22-array comparison, or output schema;
- changing the optimized runner, scientific source, runtime dependency,
  complete-290 meaning, fixed identity, legacy/golden/canonical data,
  numerical criteria, frequency/order, mode, point, resolution, or `lmax`;
- output copy/promotion, canonical write, missing-as-zero, warning
  suppression, retry, duplicate, alternate or parallel execution;
- new frequency, production, plots, scientific fixtures, Kirchhoff, paper,
  GitHub, network/install/global mutation, destructive cleanup;
- new task/subagent/proxy/descendant, `max`, or `ultra`.
