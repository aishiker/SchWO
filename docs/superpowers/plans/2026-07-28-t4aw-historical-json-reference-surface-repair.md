# T4aw Historical-JSON Reference-Surface Repair Plan

## Goal

Repair only the durable driver's misuse of canonical control-record JSON
validation on the byte-exact immutable historical legacy sidecar.

The consumed T4av producer pair remains immutable and non-reusable. Phase A
is zero-science and stops at:

```text
CHECKPOINT / HISTORICAL JSON REFERENCE SURFACE FROZEN
```

## Phase 0 — Start Gate

1. Read project/status/current T0/T4/T7/T8 handoffs and complete
   T4ar–T4aw packages and T7cu–T7cz decisions.
2. Verify candidate/ref/parent/primary HEAD and exact-four bytes.
3. Reconstruct both T4av Phase-B roots.
4. Rehash the consumed v2 root as 823 files, 117 directories,
   531851545 bytes and final index `1c1f88da...74d1`.
5. Verify PID/SID/PGID 2090, exit0/no signal/exact wait/reap/PG-empty,
   canonical stdout, empty stderr, non-reusable pair and matching audit0.
6. Preserve the exact `audit-failure` return2/output-collision record
   without treating it as a successful failure audit.
7. Prove the exact `_read_json(legacy_sidecar_path)` failure and validate
   the sidecar as strict finite duplicate-free object JSON with exact raw
   SHA/stat/content binding.
8. Reverify driver/launcher/checkpoint/runtime/complete290/reference/
   legacy/golden/warning/witness/canonical/absence/external/process/
   transient/link guards.

Any unexplained drift stops before edits.

## Phase 1 — Preserve Old Control

1. Create one fresh unique no-overwrite Phase-A evidence root.
2. Preserve exact old driver, launcher, T4av checkpoint/preflight and both
   T4av Phase-B roots.
3. Bind the consumed isolated pair as present but permanently non-reusable.
4. Preserve canonical/external identities and eight later-output absences.

## Phase 2 — Split The JSON Reader Surfaces

1. Leave the generic canonical control-record `_read_json()` byte-identical.
2. Add one dedicated immutable-historical-sidecar reader.
3. Bind it only to the exact validated legacy-sidecar role/path/hash/stat.
4. Reject invalid UTF-8/JSON, duplicate keys, non-finite constants and
   non-object top levels.
5. Do not require historical raw bytes to equal a reserialization.
6. Do not rewrite, normalize, chmod, replace or publish historical bytes.
7. Change only the literal legacy-sidecar call site in
   `_reconstruction_pair_snapshot()`.
8. Preserve the exact canonical produced-witness reader and every
   scientific/provenance gate.

## Phase 3 — Zero-Science Tests

Run every positive, negative and static/dataflow test in the frozen design
under exact Python 3.14.

Use the exact immutable historical sidecar only as a read-only parser
fixture. Do not use or inspect the consumed producer pair as positive
scientific evidence.

Build and validate fresh prospective producer and matching-audit requests
without launching either child.

Diagnosed local pre-execution fixture/helper/manifest/path/serialization/
bookkeeping defects must be preserved in immutable failed roots and
minimally corrected in fresh roots. Blind retry is forbidden.

## Phase 4 — Checkpoint

Freeze:

- old/final driver and diff;
- historical/canonical/produced-witness reader functions and call sites;
- all tests and rejection reasons;
- prospective zero-child requests;
- complete consumed T4av boundary;
- runtime/source/input/reference/legacy/golden/warning/witness/canonical/
  absence/external/process/transient/link guards;
- science invocation counts all zero.

Return the exact checkpoint and stop for root-T0 audit.

## Later Gates

Only a separate root-T0 audit and authorization permits one completely new
reconstruction producer and, after its full PASS, one matching zero-solver
audit. Any launched failure consumes that authorization and forbids retry.

Witness PASS still requires separately gated T4ar Phase C before the
optimized matrix. Matrix order and every scientific criterion remain
unchanged.
