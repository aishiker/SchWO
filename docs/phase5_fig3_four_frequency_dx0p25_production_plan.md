# Phase 5 Fig.3 Four-Frequency dx=0.25M Production Plan

Date: 2026-07-08

Status: planning-only package for T7bi review. No production solver run has
been executed by this plan.

## Scope

This plan covers a future Li-Hou-Zhao Fig.3-style high-resolution production
run with:

- frequencies `kM=[0.5,1.0,1.5,2.0]`;
- saved-data spacing `dx=dz=0.25M`;
- x-z domain `x/M,z/M in [-30,30]`;
- Route B/M4 production path for physical `h_plus` and `h_cross`;
- range-based x-z observer configs with `endpoint: true`;
- horizon/interior mask policy `r <= 2M` invalid.

This plan does not authorize or claim:

- Fig.2 strict `Psi4`;
- M5 transmission factors;
- R60/R60_K4;
- `kM=4`;
- `dx=0.2M`;
- fixtures;
- dense Fig.5/Fig.6 scans;
- Kirchhoff or Appendix D/E curves;
- paper-level or final journal-grade Fig.3 acceptance.

## Execution Options

### Option A: Rerun All Four Frequencies

Run all four draft configs into one uniform production directory:

```text
runs/phase5/fig3_four_frequency_dx0p25_production/
```

Advantages:

- simplest provenance: every NPZ/run JSON in the production directory was
  generated by the same future T8ah production slice;
- avoids ambiguity about whether the T8ae `kM=2` pilot was promoted from pilot
  status into production status;
- allows one manifest to record one production command set, one production
  verification pass, and uniform sidecar requirements;
- easiest for T7 to review as an atomic four-frequency archive.

Costs:

- reruns the expensive `kM=2.0` case even though an accepted pilot exists;
- expected wall time is higher than a by-reference route.

### Option B: Run Three Frequencies And Reference Accepted kM=2 Pilot

Run only `kM=0.5,1.0,1.5` into the production directory and include the
accepted `kM=2.0` pilot by immutable path/hash.

Advantages:

- saves the observed `kM=2.0` runtime of `4220.79 s` before plotting and
  postprocessing;
- reuses an artifact whose shape, mask, convergence, Q018 coverage, common-grid
  comparison, and hardened sidecars have already been reviewed.

Risks:

- mixes a pilot directory and a production directory in one Fig.3 archive;
- requires T7/T0 to explicitly decide that the T8ae/T8af artifact may be
  incorporated by reference;
- future readers may confuse "accepted single-frequency pilot evidence" with a
  uniform four-frequency production run unless the manifest is very explicit.

### Recommendation

Recommend **Option A: rerun all four frequencies** for the first
four-frequency `dx=0.25M` production archive.

Reasoning: the extra runtime is acceptable relative to the cost of provenance
ambiguity. A uniform production directory with four fresh NPZ/run JSON pairs is
easier to review, archive, and later cite. Option B remains available only if
T7bi/T0 explicitly decide that runtime savings matter more than uniform
production provenance.

## Q018 Policy

Q018 acceptance remains same-domain only:

```text
rmax = sqrt(30^2 + 30^2) = 42.42640687119285 M
```

Future production requirements:

- every produced run must record a Q018/radial warning summary in run JSON;
- every plot sidecar must inherit a `q018_warning_summary` field;
- for `kM=2.0`, every `evanescent_tail_suppressed` record must cover
  `rmax=42.42640687119285M`;
- the known accepted pilot values are warning count `56`, ell `153..180`,
  sectors `even/odd`, min `valid_until_r=42.472089355131786`, and margin
  `0.045682483938932705`;
- any uncovered warning, fail-closed warning, missing `valid_until_r`, or
  unreviewed warning code is a stop condition.

Lower frequencies may have no Q018 suppressed warnings, as in the accepted
`dx=0.5M` archive. They still must record warning count/codes explicitly.

## Plot And Output Policy

Production sequence:

1. Solver writes saved complex NPZ first.
2. Run provenance JSON is written per frequency.
3. Plots read saved NPZs only; plotting must not call solver, scattering,
   radial, angular, or physics production APIs.
4. Nearest audit panels are required.
5. Bilinear panels are optional display-only renders and are not numerical
   evidence.
6. Sidecars must inherit T8af detached-provenance fields.

Required sidecar fields include:

- `source_result_path`;
- `source_result_sha256`;
- `source_result_size_bytes`;
- `run_json_path`;
- `q018_warning_summary`;
- `not_paper_level_claim=true`;
- `not_final_journal_grade=true`;
- `single_frequency_resolution_evidence_only=false` for the future
  four-frequency production archive, or a clearer equivalent production-scope
  flag if T8ah defines one;
- false flags for `dx02_production`, `kM4_production`, `R60_production`, and
  `fig2_strict_psi4_artifact`;
- interpolation policy;
- `grid_spacing`;
- final adjacent pair and pass flag;
- requested DPI;
- valid/invalid counts;
- Fourier/gauge/polarization convention metadata.

The future four-frequency production claim may be "four-frequency
`dx=0.25M` saved-data production evidence" only after T8ah/T7 review. It still
must not be labeled paper-level or final journal-grade by default.
